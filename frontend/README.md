# HelpHunter — frontend

React/Vite-приложение с разделами «Главная», «Подрядчики» и «Смета». На главной нажмите «Начать подбор» или «Найти подрядчика» в шапке: условия → настоящий `POST /api/recommend` → до трёх карточек с объяснениями backend. Справочники загружаются через `GET /api/meta`. При открытии, редактировании или загрузке пресета подбор не запускается.

Доступны светлая и тёмная темы, а также RU/KZ/EN. Локализация частичная: демо-сценарии, диагностика, объяснения backend и часть подписей остаются на русском. Тема и язык сохраняются в браузере при доступном хранилище. Иллюстрация на главной статична; реальные карточки появляются после отправки формы в разделе подбора.

Кнопка «Добавить в смету +» сохраняет подрядчика в локальном списке; «В смете →» открывает смету. Смета показывает сумму стартовых цен, позволяет удалить отдельного подрядчика или очистить список и сохраняется в `localStorage`, если браузер разрешает запись. При недоступном хранилище текущая смета работает без гарантии сохранения после перезагрузки. Лимит в три карточки относится к одному ответу подбора; смета может содержать больше профилей из разных запросов. Она не привязана к дате мероприятия, не обновляет цены и доступность автоматически. Бронирование и оплата не реализованы.

## Проверенное окружение

Windows, Node.js **22.23.2**, npm **10.9.8**, Chrome **153**. React **19.3.0**, Vite **8.3.0**, Vitest **5.0.1**, Playwright **1.63.0**. Остальные версии зафиксированы в `package.json` и `package-lock.json`. ESLint 9 выбран для совместимости с peer dependencies React-плагина, без `--force` и `--legacy-peer-deps`.

Для запуска установите Node.js 22.12+ с npm. Версии выше описывают проверенное окружение; персональные пути и локальная папка `.tools` не требуются.

## Запуск

Настройте Python-окружение и запустите backend на `http://127.0.0.1:8000` по [быстрому запуску в корневом README](../README.md#быстрый-запуск). Затем откройте второй терминал для frontend. После обновления backend установите его актуальные зависимости и перезапустите процесс; `/health` должен показывать `api_version: "1.2.0"`.

Windows PowerShell, из корня:

```powershell
cd frontend
npm.cmd ci
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm.cmd run dev
```

Linux/macOS, из корня (эквивалентные команды; фактический запуск проверен на Windows):

```sh
cd frontend
npm ci
test -f .env.local || cp .env.example .env.local
npm run dev
```

Открыть **http://127.0.0.1:5173** и нажать «Начать подбор». Значения по умолчанию работают и без `.env.local`. В PowerShell `npm.cmd` позволяет запускать npm без изменения ExecutionPolicy.

## Подключение

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `/api` | Публичная база с префиксом backend, например `https://host/api` |
| `API_PROXY_TARGET` | `http://127.0.0.1:8000` | Upstream локального Vite, только серверная конфигурация |
| `VITE_API_TIMEOUT_MS` | `10000` | Срок ожидания клиента; не прекращает Python-вычисления |

Vite загружает `.env`, `.env.local`, файлы режима и переменные окружения. После изменения перезапустите dev-сервер, а production-клиент пересоберите.

**Путь сохраняется:** `/api/recommend` → Vite → `http://127.0.0.1:8000/api/recommend`. Удалять `/api` нельзя. Запросы приложения находятся только в `src/api.js`; нет автоматических повторов или кэша выдачи.

Все `VITE_*` публичны. Ключи и токены сюда не помещаются; LLM из браузера не вызывается.

## Проверки

Из `frontend/` (PowerShell: `npm.cmd`, Linux/macOS: `npm`):

```sh
npm ci
npm run lint
npm test
npm run build
npm run test:e2e
```

`npm test` запускает Vitest один раз. Моки находятся только в `src/tests/`. E2E читает CSV **в Node-процессе тестов**, проверяет настоящий сервер, не перехватывает `/recommend`.

Проверяйте backend **API 1.2.0**: `/health` должен содержать `api_version: "1.2.0"` и `dataset_version: "87d082de8481"`, `/api/meta` — полные названия городов, карточки — `city_imputed` и `price_imputed`. Номер API также доступен в `/openapi.json`. После обновления исходников перезапустите backend; наличие работающего порта не подтверждает версию процесса. Актуальные итоги прогонов — в [полном аудите](../docs/audit.md).

По умолчанию используется установленный Chrome. Если его нет:

```powershell
npx.cmd playwright install chromium
$env:PLAYWRIGHT_CHANNEL = 'chromium'
npm.cmd run test:e2e
```

```sh
npx playwright install chromium
PLAYWRIGHT_CHANNEL=chromium npm run test:e2e
```

Проверка production-сборки с **локальным** proxy на 4173:

```powershell
npm.cmd run build
$env:E2E_BUILT = '1'
npm.cmd run test:e2e
Remove-Item Env:E2E_BUILT
```

```sh
npm run build
E2E_BUILT=1 npm run test:e2e
```

Для ручного просмотра: `npm run preview`, http://127.0.0.1:4173. Playwright запускает собственный dev/preview, если порт свободен; существующий backend не останавливает. Отчёты и скриншоты: игнорируемые `test-results/` и `playwright-report/`.

Для отдельного проверочного запуска можно задать другие порты, не занимая рабочие серверы. Например, при backend на 8001:

```powershell
$env:API_PROXY_TARGET = 'http://127.0.0.1:8001'
$env:E2E_PORT = '5174'
npm.cmd run test:e2e
Remove-Item Env:API_PROXY_TARGET, Env:E2E_PORT
```

Linux/macOS: `API_PROXY_TARGET=http://127.0.0.1:8001 E2E_PORT=5174 npm run test:e2e`. `E2E_PORT` меняет и адрес браузера, и порт запуска dev/preview; `E2E_BUILT=1` выбирает собранный клиент. По умолчанию порты — 5173 для dev и 4173 для preview.

## Production-маршрутизация

`dist/` — статические файлы. Dev/preview proxy не является production-инфраструктурой. Применимый вариант — **same-origin reverse proxy**: хост отдаёт `dist/`, а `/api/` направляет в существующий FastAPI с сохранением пути. Конфигурация для передачи ответственному за развёртывание:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
}
location / {
    root /srv/hackalem/frontend/dist;
    try_files $uri $uri/ /index.html;
}
```

Собирать с `VITE_API_URL=/api`. Внешний сервер не настраивался. Проверка preview подтверждает собранный клиент и локальный маршрут, **не** публичный deployment.

Для раздельных доменов нужны публичный `VITE_API_URL` с `/api` и разрешённый origin frontend в backend. По умолчанию API 1.2.0 разрешает HTTP-origin `localhost` и `127.0.0.1` на портах 3000, 5173 и 4173. Переменная backend `CORS_ORIGINS=https://events.example.com,https://preview.example.com` заменяет этот список; origin задаются без пути. Подробнее — в [backend/README.md](../backend/README.md#cors-и-размещение). Same-origin proxy не требует отдельного разрешения CORS. Продакшен-домен ещё не выбран.

## Справочники и ограничения

В API 1.2.0 `/api/meta` возвращает корректные полные названия городов, категории, форматы, языки и `dataset_version`. Все справочники текущего сервера используются напрямую. В адаптере оставлена совместимость с прежним дефектом: только если города состоят из отдельных букв, используется `src/data/cities.json`. Это справочник городов, а не запасной каталог рекомендаций; версия каталога старого сервера при такой подстановке не подтверждена. Подбор всегда выполняет backend.

`scripts/export-cities.js` читает **backend/data/contractors.csv** полноценным CSV-парсером. Экспортируются только города, путь и SHA-256 — без профилей, флагов, цен, описаний и календарей. Хеш считается по UTF-8 с переводами строк LF: автоматическое преобразование LF/CRLF при клонировании не меняет версию данных. Сборка/тесты проверяют хеш. После осознанного обновления CSV:

```sh
npm run metadata:export
npm test
```

Календарь **23.09–31.12.2026** включает границы. Бюджет — целые тенге **больше нуля**, не больше `9007199254740991`; пустой бюджет не равен нулю. Длительность конечна и положительна либо `null`; форма принимает десятичную запятую и перед отправкой преобразует ввод в JSON-число. Язык — один либо `null`; пробельная строка на сервере становится `null`. Цены не умножаются на часы. API отклоняет числовые строки и логические значения вместо чисел, нецелые бюджет/limit, `Infinity`/`NaN`, пустые обязательные поля и даты вне окна с HTTP 422. Клиент читает `detail[].loc` и `detail[].msg`; `input`/`ctx` ему не требуются.

`synthetic`, `price_imputed` и `city_imputed` приходят из текущего API. Компоненты показывают соответствующие пометки; отсутствующие признаки старого сервера не подменяются значением false. `dataset_version` ответа виден в технических деталях и учитывается при сравнении дат. Версия — 12 символов SHA-256 нормализованного CSV; это идентификатор данных, не алгоритма. Объяснения показываются без переписывания: конкретная особенность цитируется из профиля, а недостаточность описания обозначается явно. Актуальный контракт — в [интеграционном отчёте](../docs/frontend-integration.md), результаты содержательной проверки — в [аудите](../docs/audit.md).

## Устройство

- `App.jsx`, `components/` — навигация между главной, подбором и сметой, тема и язык, форма, пресеты, карточки и диагностика.
- `api.js` — fetch, AbortController, таймаут, HTTP/JSON/422.
- `adapters.js` — единая проверка и преобразование действующего контракта.
- `hooks/useRecommendations.js` — снимок запроса, отмена, защита от поздних ответов, сравнение дат.
- `utils/` — проверка чисел/даты и форматирование без UTC-сдвига.
- `src/tests/`, `e2e/` — изолированные тесты клиента и настоящая интеграция.

Справочные материалы: [Vite](https://vite.dev/guide/), [браузеры Playwright](https://playwright.dev/docs/browsers). Сведения о backend основаны на его локальном коде и живых ответах.
