# HelpHunter — подбор подрядчиков для мероприятий

Проект команды **QLCD** для HackAlem. Организатор задаёт город, дату, формат мероприятия, категорию, бюджет и дополнительные условия. HelpHunter проверяет каталог и показывает **до трёх подходящих подрядчиков** с объяснениями выбора. Если вариантов нет, пользователь видит причину и может изменить условия.

Продукт сокращает ручной перебор анкет: учитывает занятость, отсеивает неподходящие варианты и помогает составить предварительную смету. Смета сохраняется только в браузере и суммирует стартовые цены. Бронирование, оплата, заявки и уведомления подрядчикам не входят в проект.

**Для жюри:** [запустить](#быстрый-запуск) → [проверить за 5 минут](#проверка-за-5-минут) → [посмотреть пайплайн](#как-работает-подбор) → [повторить тесты](#автоматические-проверки). [Известные ограничения](#известные-ограничения) описаны отдельно.

## Быстрый запуск

Нужны **Git**, **Python 3.11** и **Node.js 22.12+ с npm**. Проверенное окружение: Windows, Python 3.11.16, Node.js 22.23.2, npm 10.9.8. Данные уже лежат в репозитории; аккаунты, ключи API и отдельная база данных не требуются. Интернет нужен для клонирования и установки зависимостей.

Если репозиторий ещё не скачан:

```sh
git clone https://github.com/BAITC-Hacks/hack-0edd372c-qlcd.git
cd hack-0edd372c-qlcd
```

Откройте **два терминала в корне репозитория**. Оба сервера должны оставаться запущенными.

### Windows PowerShell

Терминал 1 — backend:

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Проверка за 5 минут

Инструкция использует русские подписи; при необходимости выберите **RU** в меню языка. Проверяйте раздел подбора: иллюстрация на главной не является ответом API.

1. Откройте приложение и нажмите **«Начать подбор →»**.
2. Разверните **«Демо-сценарии»**, выберите сценарий, нажмите **«Заполнить форму»**, затем **«Подобрать»**. Заполнение формы само по себе не отправляет запрос.
3. Последовательно выполните **A, B, C** из таблицы. Проверьте количество карточек, текст объяснений и блок **«Как выполнен подбор»**.
4. Повторите **A** с теми же условиями: порядок должен остаться прежним. В интерфейсе рядом с результатом показано измеренное время запроса; ориентир задания — до 10 секунд.
5. Выполните **E1**, затем **E2** без промежуточного сброса: изменяется только дата. Сравните число подходящих, счётчик занятых и пояснение изменения выдачи.

Идентификаторы видны в карточках; их также можно сверить в JSON-ответе `/api/recommend` через Swagger или вкладку Network браузера. В сценарии E календарь CSV подтверждает: `HK-80581` свободен 15 октября и занят 16 октября. API передаёт только агрегированные причины исключения, поэтому интерфейс показывает изменение счётчика занятых, без персонального утверждения об исключённом профиле.

**Дополнительная проверка интерфейса:** измените бюджет без отправки — появится отметка, что показан предыдущий результат. Нажмите «Подобрать», чтобы применить новые условия. Добавьте карточку через «Добавить в смету +», откройте «Смета», проверьте сумму и удалите позицию. Смета может включать подрядчиков из нескольких запросов; она не подтверждает их доступность на общую дату.

**Проверка объяснений:** закройте имена в карточках и сопоставьте аргументы с ценой, условиями и описанием каждого профиля. Одного общего «подходит по бюджету и свободен» недостаточно. Ищите конкретную особенность: опыт, состав, репертуар, технику оформления или оборудование площадки. Backend выбирает эти сведения из исходного описания и помечает их как цитату профиля; прохождение технических тестов не заменяет содержательную проверку.

## Как работает подбор

```text
Форма React → POST /api/recommend → каталог CSV
    → город и категория → проверка ограничений
    → объяснения и баллы → стабильная сортировка → до 3 карточек
```

1. **Источник:** backend проверяет структуру и значения CSV при старте. Повреждённые данные останавливают загрузку с указанием файла, строки и колонки. Frontend получает справочники и отправляет введённые условия; собственный каталог для подбора в браузер не загружается.
2. **Фильтры:** сначала город и категория, затем занятость на дату → бюджет → формат мероприятия → язык → длительность. Профиль исключается по **первой** неуспешной проверке. Счётчики причин не пересекаются: `total_category_city = eligible_count + сумма excluded_summary`.
3. **Объяснение:** собирается из проверенных условий и конкретной особенности из описания. `semantic.py` разбивает текст на предложения/пункты и выбирает факты по тематическим словарям; приветствия и рекламные слоганы отбрасываются. Это лексический алгоритм. Объяснение создаётся в backend и показывается клиентом без переписывания. Если содержательной особенности нет, это прямо указано в ответе.
4. **Ранжирование:** балл складывается из запаса бюджета, учёта запрошенного языка/длительности, наличия конкретной особенности и её соответствия категории или формату запроса; точная формула приведена ниже. Сортировка: балл по убыванию, стартовая цена по возрастанию, затем ID. При одинаковых условиях, данных и версии алгоритма повтор сохраняет порядок. Балл не является процентом качества или вероятностью успеха.
5. **Ответ:** до трёх карточек, исходные условия, число рассмотренных и подходящих профилей, причины исключения и версия каталога. В карточках передаются признаки `synthetic`, `city_imputed`, `price_imputed`. При пустом результате backend различает отсутствие категории в городе и отсев существующих профилей.

### Формула ранжирования

После прохождения всех фильтров: `score = round(B + L + D + E, 2)`.

| Слагаемое | Точное правило из `backend/app/recommender.py` |
| --- | --- |
| `B` — запас бюджета | `max(0, 30 × (1 − price_from_kzt / budget_kzt))` |
| `L` — язык | `20`, если язык запрошен; иначе `0`. Все прошедшие фильтр профили получают одинаковое значение |
| `D` — длительность | `5`, если длительность не задана; `10`, если она задана, но у профиля `max_hours = null`; иначе `min(15, 5 + 10 × max(0, max_hours − duration_hours) / max(max_hours, 1))` |
| `E` — факты описания | `5` за `profile` — найденную конкретную особенность; ещё `10` за `relevant_profile` — соответствие этой особенности категории или формату запроса. Без содержательного фрагмента — `0` |

Словари распознают признаки опыта, состава, инструментов, репертуара, стиля съёмки, оформления и оборудования. При выборе учитываются категория, конкретность и формат мероприятия; равенство разрешается позицией фрагмента в исходном тексте. Одного совпадения слова «свадьба» или наличия рекламного слогана для бонуса недостаточно. Алгоритм не подтверждает достоверность заявлений самого подрядчика вне датасета.

**Использование AI:** Codex применялся при разработке, исправлении и тестировании проекта. В текущем работающем пайплайне нет LLM, эмбеддингов или вызовов платных AI API. Поиск и объяснения детерминированы; модель на 66 записях не дообучалась.

### Проверка API без интерфейса

Откройте [Swagger](http://127.0.0.1:8000/docs) → `POST /api/recommend` → **Try it out**. Вставьте JSON сценария A и нажмите **Execute**:

```json
{
  "city": "Алматы",
  "event_date": "2026-10-10",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1500000,
  "duration_hours": 6,
  "language": "русский",
  "limit": 3
}
```

Ожидается HTTP **200**, `status: "matches_found"`, `dataset_version: "87d082de8481"`, `total_category_city: 10`, `eligible_count: 5`, три элемента `results` и `excluded_summary: {"booked": 4, "over_budget": 1}`. Сверьте порядок ID с таблицей сценариев и повторите запрос; полный JSON доступен в [примерах API](docs/api-examples.json).

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Работоспособность, количество профилей, версии каталога и API |
| `GET /api/meta` | Справочники городов, категорий, форматов и языков, версия каталога |
| `POST /api/recommend` | Рекомендации; статусы `matches_found`, `no_category_in_city`, `no_candidates_meet_conditions` |

Пустая выдача — штатный ответ **200**. Неверная дата, дата вне окна, строки из пробелов в обязательных полях, нулевой/отрицательный бюджет, `Infinity` и `NaN` возвращают **422**. Ответ содержит `detail` с полем `loc`, типом `type` и сообщением `msg`; исходные значения и внутренний контекст ошибки не возвращаются. Недоступность сервера отображается в UI как техническая ошибка, а не как отсутствие подрядчиков. [Полный контракт](docs/frontend-integration.md).

## Данные и правила ввода

Каталог [backend/data/contractors.csv](backend/data/contractors.csv) содержит **66 профилей**, включая **13 синтетических**, в **17 категориях**. По городам: Алматы — 50, Астана — 15, Зарубежье — 1. Карточки помечаются по `synthetic` из API; `price_imputed` и `city_imputed` указывают, что цена или город проставлены при подготовке данных. Например, в B у `HK-39372` проставлена цена; в F у `HK-64395` — цена и город.

`dataset_version` — первые 12 символов SHA-256 CSV после нормализации переводов строк CRLF → LF. Текущее значение: **`87d082de8481`**. Оно идентифицирует данные, но не версию алгоритма: после изменения кода при том же CSV ранжирование может измениться.

- Доступные даты: **23.09.2026–31.12.2026 включительно**. Это фиксированное окно датасета; при проверке в другой день используйте даты из демо.
- Бюджет — положительное целое JSON-число тенге **на одного подрядчика**, не больше `9007199254740991` — предела точности целых в JavaScript. Цены стартовые **за мероприятие**, на часы не умножаются. `limit` — целое число от 1 до 3. Строки с числами, дроби и логические значения для этих полей API не принимает.
- Длительность — конечное положительное JSON-число или `null`. Пустой `max_hours` в данных означает, что ограничение длительности для профиля не применяется. Форма преобразует допустимый пользовательский ввод в JSON-число перед отправкой.
- Язык — одно значение или без ограничения. API обрезает пробелы по краям; пустой язык становится `null`, а пустые обязательные город, категория и формат отклоняются.
- Свободен означает отсутствие даты в календаре `busy_dates` текущего CSV. Фактическая доступность и окончательная стоимость у подрядчика не подтверждались.

При обновлении каталога загрузчик требует ровно 13 известных колонок, уникальные непустые ID, корректные списки категорий/форматов/языков, целые неотрицательные цены и флаги `True`/`False`. Даты занятости должны быть реальными датами `YYYY-MM-DD` внутри окна; часы — конечным положительным числом или пустым значением. Пустая цена не заменяется нулём. Подробности и примеры ошибок — в [backend/README.md](backend/README.md#проверка-каталога).

Если Chrome нет: выполните `npx.cmd playwright install chromium`, установите `$env:PLAYWRIGHT_CHANNEL = 'chromium'` и повторите E2E. Команды проверки собранного клиента и Linux/macOS описаны в [frontend/README.md](frontend/README.md#проверки).

E2E используют настоящий `/api/recommend`, сверяют ответы с CSV и проверяют сценарии на экранах **1366×900** и **390×844**. Тестовые моки применяются только в unit/component-тестах. Отчёт браузерных проверок: `frontend/playwright-report/index.html`; открыть из `frontend/` можно командой `npx.cmd playwright show-report`. Отчёты и скриншоты генерируются локально и не включены в Git.

`npm run build` также проверяет, что экспорт справочника городов соответствует CSV. Frontend-зависимости устанавливаются по `package-lock.json`; прямые зависимости backend закреплены в `requirements.txt`.

### Результаты проверки

Актуальные команды, результаты и оставшиеся ограничения после исправлений **API 1.2.0** приведены в [полном аудите](docs/audit.md). Живые сценарии описаны в [docs/demo.md](docs/demo.md), ответы сохранены в [docs/api-examples.json](docs/api-examples.json). Проверки охватывают клиент, настоящий API, валидацию запросов и CSV, стабильность выдачи и объяснения. Прежние прогоны на API 1.1.0 не подтверждают состояние новой версии.

Это локальная проверка. Публичный сервер не развёрнут, production-нагрузка не измерялась. Для самостоятельного измерения времени используйте UI или Network браузера. Таймаут клиента — **10 секунд**; он ограничивает ожидание, но не гарантирует время ответа и не останавливает вычисление backend.

## Если запуск не удался

| Симптом | Что проверить или сделать |
| --- | --- |
| `Port 5173 is already in use` | Откройте `http://127.0.0.1:5173`: возможно, этот frontend уже запущен. Для второй копии: `npm.cmd run dev -- --port 5174`, затем откройте порт 5174. Стандартные E2E используют 5173 |
| Порт 8000 занят | Проверьте `/health` и `/docs` существующего сервера. Для второго backend задайте `--port 8001`, а в `frontend/.env.local` — `API_PROXY_TARGET=http://127.0.0.1:8001`; перезапустите Vite |
| Техническая ошибка / справочники не загрузились | Откройте `/health`, проверьте терминал backend и `API_PROXY_TARGET`. Сверьте настройки с `.env.example`; после изменения `.env` перезапустите frontend |
| `No module named app` | Команда Uvicorn должна выполняться из `backend/`, через Python созданного `.venv` |
| `node`, `npm` или `python` не найдены | Проверьте установку и PATH, заново откройте терминал. В PowerShell используйте `npm.cmd`; Python можно вызвать через `py -3.11` |
| Ошибка актуальности справочника городов при build/test | Если CSV был намеренно обновлён, выполните из `frontend/` `npm.cmd run metadata:export`, затем повторите тесты и сборку |
| Дата отклонена / HTTP 422 | Используйте окно 23.09–31.12.2026, целый бюджет больше нуля и конечную положительную либо пустую длительность. При прямом вызове API сверяйте `detail[].loc` и `detail[].msg` |
| Сервер не запускается с `DatasetValidationError` | Исправьте указанную строку и колонку CSV; проверка каталога выполняется до приёма запросов |
| После обновления сохранилась старая выдача | Проверьте `api_version` в `/health`: требуется `1.2.0`. Перезапустите backend из актуального окружения; при смене зависимостей повторите `pip install -r requirements.txt` |

## Известные ограничения

- **Объяснения зависят от исходных описаний.** В версии 1.2.0 конкретные особенности выбираются отдельно от общих условий; приветствия и рекламные слоганы не дают бонус. Если данных о свойствах услуги недостаточно, ответ это сообщает. Факты взяты из профилей и не проверены у подрядчиков; содержательную оценку и результаты проверок смотрите в [аудите](docs/audit.md).
- **Ранжирование детерминированное, но эвристическое.** Тематические словари ограничены, а веса не обучались на пользовательской обратной связи. Возможное развитие — семантический поиск и измерение качества рекомендаций с сохранением стабильности результата.
- **Персональных причин исключения нет:** API сообщает общие счётчики; интерфейс не может подтвердить причину отсутствия конкретного профиля в top-3 только по новому ответу.
- **Смета локальная:** хранится в `localStorage` данного браузера, не привязана к дате и не перепроверяет доступность. Локализация RU/KZ/EN частичная; объяснения backend и часть служебных подписей остаются на русском. Для проверки используйте RU.
- **Публичное размещение не выполнено.** Нужны отдельная настройка серверов и маршрутизация `/api`; Vite preview служит локальной проверке сборки.
