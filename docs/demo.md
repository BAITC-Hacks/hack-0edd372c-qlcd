# Живая демонстрация

Открыть http://127.0.0.1:5173 при работающем API на 8000. Развернуть «Демо-сценарии», выбрать сценарий, нажать «Заполнить форму», затем **«Подобрать»**. Пресеты содержат только параметры; каждый подбор — новый HTTP-запрос.

## Данные

`backend/data/contractors.csv`, SHA-256:
`87d082de8481f63795ba9d5b9509b5ffbdeabe3f99efd28b114be780df35d422`.

66 записей, 13 synthetic. С исходным файлом из Downloads все разобранные CSV-записи совпали; байтовые хеши отличаются, поэтому в проверках используется файл backend. Окно календаря фиксировано: 23.09–31.12.2026. Нет привязки к сегодняшней дате.

## Повтор, смена даты и площадки

1. **Повтор A:** три отправки подряд и новый браузерный контекст возвращают одинаковый полный бизнес-ответ. Каждый раз выполняется POST; измеренное клиентское время не является частью сравнения.
2. **E1:** Астана, 15.10.2026, свадьба, Ведущий, 1 000 000 ₸; язык/длительность не заданы. 5 исходных, 3 допустимых; порядок API: HK-37181, HK-80581, HK-97041; booked=2.
3. **E2:** только дата 16.10.2026. 5 исходных, 2 допустимых: HK-37181, HK-97041; booked=3. CSV-аудит подтверждает, что HK-80581 занят 16-го и не занят 15-го. UI не приписывает ему персональную причину: API сообщает только агрегат.
4. **F:** Алматы, 14.11.2026, свадьба, Банкетный зал, 6 500 000 ₸, 6 ч, русский. 7 исходных, 2 допустимых: HK-64395, HK-90011; booked=5. Площадки проходят тот же календарный фильтр.
5. Изменить бюджет без отправки: прежние карточки сохраняют снимок старых условий и подпись о черновике. Сброс убирает их; ошибка сервиса показывает техническое состояние без запасной выдачи.

Не обещается, что любые две даты меняют выдачу. Новая дата сравнивается только при одинаковых остальных условиях и источнике API; известное изменение версии данных также сбрасывает сравнение.

## Время

UI измеряет `performance.now()` вокруг настоящего обращения API (включая разбор и проверку ответа). E2E отдельно записывает HTTP-длительность браузера `responseEnd − requestStart` и время от автоматизированного нажатия до получения JSON. Они различаются из-за накладных расходов браузерного управления; это не константы и не кэш.

В сохранённом dev-прогоне HTTP занял **3,48–6,50 мс**, автоматизированное нажатие → JSON — **34,38–90,94 мс** для 14 запросов A–F на двух ширинах. Полные ответы и индивидуальные замеры: [api-examples.json](api-examples.json). Это отдельный записанный прогон; последующие проверки могут дать другое время. Клиентский таймаут — **10 секунд**, без автоматических повторов; он не обещает остановку серверного вычисления. Локальные результаты не являются замером production-нагрузки.
